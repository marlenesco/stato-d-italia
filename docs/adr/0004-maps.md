# ADR 0004: mappe statiche PMTiles e valori tematici separati

**Stato:** accepted

## Contesto

I confini amministrativi sono asset relativamente statici, mentre i valori
ambientali cambiano per metrica, anno e release. Duplicare geometrie in ogni
dataset tematico aumenterebbe fortemente dimensioni e traffico.

## Decisione

Le geometrie amministrative ISTAT generalizzate vengono trasformate in PMTiles.

PMTiles contiene **solo geometria e attributi minimi di join/navigazione**. I
valori tematici restano asset delivery separati.

Per mappe storiche, la feature cartografica deve essere identificabile tramite la
versione territoriale coerente con la data di riferimento, non solo tramite il
territorio logico corrente.

Join concettuale:

```text
thematic value
  -> territory_version_id
  -> geometry_version_id / PMTiles feature
```

Gli asset tematici devono dichiarare:

- metric ID;
- reference year/period;
- territory level;
- territory reference date/version;
- unit;
- provenance reference;
- release/schema version.

MapLibre è il renderer previsto per la futura UI e fa il join client-side.

## Accessibilità

La mappa non sarà mai l'unico modo di leggere un'informazione. Ogni vista
cartografica significativa deve avere un'alternativa tabellare, ranking o testuale.

## Conseguenze

- La stessa geometria può essere riutilizzata da molte metriche.
- Uno slider temporale può cambiare i valori senza duplicare i poligoni.
- Quando cambiano i confini può essere necessario caricare una diversa versione
  PMTiles, invece di riutilizzare sempre la geometria corrente.

## Alternative scartate

- **GeoJSON completo per ogni metrica/anno:** duplicazione e payload maggiori.
- **Geometria dentro il canonical tabellare:** mescola responsabilità analitiche e
  cartografiche.
- **Join sul solo codice corrente:** non sicuro per serie storiche.
